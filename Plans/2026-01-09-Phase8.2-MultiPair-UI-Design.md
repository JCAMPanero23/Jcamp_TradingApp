## Executive Summary

Design for enhancing the existing **BacktestWindow** and **ChartViewerWindow** to support multi-pair backtesting with synchronized playback. This approach maintains backward compatibility while adding the ability to test multiple currency pairs simultaneously with a unified timeline.

**Core Principle:** Single UI that handles both single-pair and multi-pair workflows seamlessly.

- Reuse existing UI infrastructure (tabs, layouts, controls)

**Key Components:**
1. **BacktestWindow** - Enhanced with multi-pair selection
2. **ChartViewerWindow** - Enhanced with pair tabs and unified timeline

### Chart Rendering

**Pair-Specific Rendering:**
```csharp
private void RenderChartForPair(string pair, int barIndex)
{
    if (!_pairData.ContainsKey(pair))
        return;

    var candles = _pairData[pair];
    var visibleCandles = candles.Take(barIndex + 1).ToList();

    // Clear and redraw chart
    ChartPlot.Plot.Clear();

    // Render candlesticks
    RenderCandlesticks(visibleCandles);

    // Render indicators (EMAs, etc.)
    RenderIndicators(visibleCandles);

    // Render trades for this pair only
    var pairTrades = _allTradesChronological
        .Where(t => t.Symbol == pair && t.EntryBarIndex <= barIndex)
        .ToList();
    RenderTradeMarkers(pairTrades, barIndex);

    ChartPlot.Refresh();
}
```

### Timeline Synchronization

Timeline advances bar-by-bar for ALL pairs simultaneously.
Each pair has its own M15 data, but they're all time-aligned.
```

**Key Insight:**

- Chart shows current pair's data up to that position
- Switching pairs shows different chart at same timeline position

private void RecentTradeSelected(object sender, SelectionChangedEventArgs e)
{
    if (RecentTradesListView.SelectedItem is TradeListItem trade)
    {
        // 1. Pause playback if running
        if (_isPlaying)
            StopPlayback();

        // 2. Switch to correct pair tab if different
        if (trade.Symbol != _currentPair)
        {
            SwitchToPairTab(trade.Symbol);
        }

        // 3. Jump timeline to trade entry time
        JumpToTrade(trade.TradeId);

        // 4. Highlight trade marker on chart
        HighlightTradeMarker(trade.TradeId);

        // 5. Show trade details panel
        DisplayTradeDetails(trade);

private void SwitchToPairTab(string pair)
{
    _currentPair = pair;

    // Find and select the tab
    foreach (TabItem tab in PairTabControl.Items)
    {
        if (tab.Tag as string == pair)
        {
            PairTabControl.SelectedItem = tab;
            break;
        }
    }
}
```

3. **Automatically:** Bottom tab switches to GBPUSD
4. **Automatically:** Chart redraws to show GBPUSD at 14:15
5. **Automatically:** Trade marker #44 is highlighted
6. Trade details panel shows full information

```csharp
private void UpdateAccountStatistics(int barIndex)
{
    // Get trades up to current bar
    var closedTrades = _allTradesChronological
        .Where(t => t.ExitBarIndex <= barIndex)
        .ToList();

    var openTrades = _allTradesChronological
        .Where(t => t.EntryBarIndex <= barIndex && t.ExitBarIndex > barIndex)
        .ToList();

    // Calculate realized balance
    double balance = _initialBalance;
    foreach (var trade in closedTrades)
    {
        balance += trade.ProfitLoss;
    }

    // Calculate unrealized P&L for open positions
    double unrealizedPL = 0;
    foreach (var trade in openTrades)
    {
        double currentPrice = GetCurrentPrice(trade.Symbol, barIndex);
        unrealizedPL += CalculateUnrealizedPL(trade, currentPrice);
    }

    // Equity = Balance + Unrealized P&L
    double equity = balance + unrealizedPL;

    // Calculate statistics
    int wins = closedTrades.Count(t => t.RMultiple > 0);
    int total = closedTrades.Count;
    double winRate = total > 0 ? (wins * 100.0 / total) : 0;
    double totalR = closedTrades.Sum(t => t.RMultiple);
    double avgR = total > 0 ? totalR / total : 0;

    // Update UI
    BalanceText.Text = $"${balance:N2}";
    EquityText.Text = $"${equity:N2}";
    TotalRText.Text = $"{totalR:+0.00;-0.00}R";
    WinRateText.Text = $"{winRate:F1}% ({wins}/{total})";
    AvgRText.Text = $"{avgR:+0.00;-0.00}R";
}

private double CalculateUnrealizedPL(Trade trade, double currentPrice)
{
    double priceDiff = trade.Side == "BUY"
        ? currentPrice - trade.EntryPrice
        : trade.EntryPrice - currentPrice;

    double riskAmount = trade.EntryPrice * trade.PositionSize * trade.RiskPercent;
    double slDistance = Math.Abs(trade.EntryPrice - trade.StopLoss);

    return (priceDiff / slDistance) * riskAmount;
}
```

### API Client Enhancement

**New Method in BacktestApiClient.cs:**
```csharp
public async Task<MultiPairBacktestResults> RunMultiPairBacktestAsync(
    MultiPairBacktestRequest request,
    IProgress<BacktestStatus> progress)
{
    // Validate request
    if (request.Pairs == null || request.Pairs.Count == 0)
        throw new ArgumentException("At least one pair must be selected");

    if (request.Strategies == null || request.Strategies.Count == 0)
        throw new ArgumentException("At least one strategy must be selected");

    // Report progress
    progress?.Report(new BacktestStatus
    {
        Message = $"Running backtest for {request.Pairs.Count} pairs...",
        Progress = 0
    });

    // Call Python API
    var response = await _httpClient.PostAsJsonAsync(
        "/backtest/multi-pair",
        request
    );

    response.EnsureSuccessStatusCode();

    // Parse results
    var results = await response.Content.ReadAsAsync<MultiPairBacktestResults>();

    progress?.Report(new BacktestStatus
    {
        Message = "Backtest complete!",
        Progress = 100
    });

    return results;
}
```

## Appendix: Key Design Decisions

### Why Option B (Enhanced Existing Windows)?

**Pros:**
- ✅ Reuse existing UI infrastructure
- ✅ Single unified interface
- ✅ Backward compatible
- ✅ Cleaner UX (no separate menu entries)
- ✅ Faster implementation (less new code)

**Cons:**
- ❌ Slightly more complex code (single/multi-pair logic)
- ❌ Risk of breaking existing functionality (mitigated by testing)

**Decision:** Option B is the right choice because it maintains simplicity for users while providing powerful multi-pair capabilities.

---

### Why Chronological Trade List (Option A)?

**Rationale:**
- Matches MT5 behavior (familiar UX)
- Easy to see natural trading flow across pairs
- Simpler implementation than grouped/filtered views
- Can add filters later if needed

---

### Why Unified Timeline?

**Rationale:**
- Simplifies playback engine (single timeline position)
- Enables realistic multi-pair simulation
- Makes statistics calculation straightforward
- Foundation for Phase 8.3+ (multi-pair orchestrator)
